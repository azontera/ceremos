# CEREMOS 現行仕様（2026-09-19 確定）

旧 `docs/リニューアル仕様書_v1.md`（営業OS構想を含む）は廃止し、本書が現行の仕様。**本書の構成（特に案件画面のタブ）を変える場合はユーザー（寺沢さん）の明示承認が必要。**

## 1. コンセプト（3行）
- 結婚式場・宴会場の「受注〜当日運営〜請求・アフター」を1案件1画面で回すERP。
- スタッフはPCで案件を進め、お客様はスマホ（PWA）で自分の案件を見て入力する。
- 営業支援（診断・攻略・AI生成）は持たない。テンプレ一式（JSON）で見積〜進行表まで一括セットアップする。

## 2. ロール
| ロール | 主な権限 |
|---|---|
| admin（管理者） | 全権。ユーザー・マスタ・設定・監査 |
| manager（支配人） | 案件・見積・発注・進行・席次の編集。料理・選曲は閲覧 |
| planner（プランナー） | 案件の主担当。見積・打合せ・進行・席次・選曲・お客様アカウント発行 |
| 専門スタッフ（chef / audio / mc / dress / florist / photo / service） | 案件閲覧＋自分の担当モジュールのみ編集（例: chef=料理、audio=選曲）。発注は自分の部門のみ |
| couple（お客様） | 自分の案件のみ。お見積り確認・カタログ「えらぶ」・ゲスト入力・選曲・チャット・ヒヤリング回答 |

ログインは全ロール共通（メール＋パスワード）。セルフ登録・承認・業者ログインは無い。お客様アカウントはプランナーが案件画面「お客様アカウント」から発行する（`POST /api/v1/cases/[id]/customers`）。

## 3. 業務フロー
### スタッフ
新規案件（種別・日時・会場・テンプレ一式を選択）→ お客様アカウント発行 → ヒヤリング回答を確認 → 見積（下書き→確定）→ 打ち合わせ記録・席次・進行表/MC台本・選曲・料理/アレルギー・発注 → 当日運営（/live：進行ボード・再生プレイヤー・映像ウィンドウ）→ 請求・入金 → アフター（連絡・引き継ぎ・クレーム記録）。

### お客様
招待（プランナーがアカウント発行・IDとPWを渡す）→ ログイン → ヒヤリング（10問、/survey）→ ゲスト入力（席次・婚礼は新郎側/新婦側で分担）→ お見積り確認・カタログで「えらぶ」→ 選曲（当日の流れの中）→ 連絡（チャット）。

## 4. 案件画面のタブ構成（固定）
`/cases/[id]?tab=…`。1タブ＝1業務。タブ内はセクション見出し（`.section-h` + id）で縦に並び、`?tab=xxx#anchor` で直接ジャンプできる。

**スタッフ 5タブ**
| タブ | セクション（上から） |
|---|---|
| 📌 案件 `info` | 基本情報 `#info` → お客様アカウント `#account` → 打ち合わせ記録 `#meetings` → タスク・準備チェックリスト `#tasks` → ヒヤリング回答 `#survey`（閲覧・折りたたみ）→ アフター `#after` → 失注（最下部・控えめ） |
| 💰 お金 `money` | 見積 `#quotes` → カタログ `#catalog` → 発注 `#orders` → 料理・アレルギー `#meals` → 請求・入金 `#billing` |
| 🪑 席次 `seating` | プレビュー＋「✏編集する」（編集は `/cases/[id]/seating`） |
| 📋 進行 `rundown` | 進行表＋MC台本 `#rundown` → 選曲 `#songs` → 控室・厨房・スタッフ割当 `#resources`（DayVenueChart＋Assignments）。開催前日〜当日は「▶ 当日運営」（/live）リンク |
| 💬 連絡 `chat` | チャット `#chat` → 添付ファイル `#attachments` |

**お客様 4タブ**
| タブ | 内容 |
|---|---|
| 💰 お見積り `money` | お支払いスケジュール → お見積り → えらぶ（カタログ） `#catalog` |
| 🪑 席次 `seating` | ゲスト入力・席次プレビュー（担当側のみ編集） |
| 📋 当日の流れ `rundown` | 進行表（閲覧）→ 選曲 `#songs` |
| 💬 連絡 `chat` | チャット → 添付 |

旧タブ名（quotes / catalog / orders / meals / billing / songs / resources / meetings / after / steps …）は `TAB_ALIAS` で新タブ＋アンカーへリダイレクトする（過去リンク・通知を壊さない）。スマホ下部ナビ（お客様）＝ホーム／お見積り／席次／当日の流れ／連絡。サイドバー（スタッフ）＝ダッシュボード／案件／カレンダー／顧客／管理（テンプレート・カタログ管理、adminのみユーザー・マスタ・設定・操作履歴）／成果。

## 5. 見積の状態
`draft`（下書き）→ `confirmed`（確定）／`archived`（旧版）。定義は `src/lib/quote-status.ts`（旧 approved / customer_confirmed は読み取り時に確定扱い）。確定は quotes 編集権を持つスタッフが行い、確定時に他版をアーカイブし発注を自動作成する。確定済みは直接編集せず「新Ver作成」。カタログ→見積反映はサーバーが定価を強制。

## 6. ダッシュボード
- スタッフ: 未対応クレーム → 件数（本日／今週／未処理タスク／見積下書き・未入金）→ 今日の予定・今週の開催 → タスク（期限超過を先頭）・見積下書き中・未入金（各案件の該当タブへリンク）。
- お客様: 「今やること」（ヒヤリング未回答・宿題・お見積り確認・ゲスト入力・選曲・次回打ち合わせ）＋4タブとヒヤリングへのクイックリンク。

## 7. 2026-09-19 に意図して削除したもの（理由）
- 営業OS層（AIヒヤリング診断・顧客攻略・商談ステップ・TabAdvice・お客様プランウィザード・見積おすすめ）… 現場で使われず、案件画面を複雑にしていた。
- テンプレのAI生成・案件からの逆生成 … テンプレはJSON一式を管理画面で読み込む方式に一本化。
- 公開カタログ（/catalog）… 要ログインのカタログ「えらぶ」で足りる。
- 業者ログイン（/vendors）… 業者は発注書印刷とマスタ管理で足りる。業者マスタ・カタログ管理は残す。
- お客様セルフ登録・メール認証・承認待ち・QR登録 … アカウントはプランナーが発行する方が確実。メール送信機能ごと廃止。
- 見積の「お客様確認」「支配人承認」状態 … 実運用は下書き→確定の2段階で十分。
- LINE通知・freee/Google/Resend連携の記述 … 未使用の外部連携を整理。
- 案件画面の独立タブ「打ち合わせ」「選曲」「リソース」「えらぶ」 … 5タブ／4タブに集約（本書4章）。

DBカラム（hearingJson / lostStep / approved / emailVerified / User.vendorId / Case.slot）はデータ保全のため残置。
