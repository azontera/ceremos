# Wedding ERP 本番デプロイ手順

社内スタッフ・業者・新郎新婦が各自の端末からHTTPSで使える状態にするための手順です。
推奨構成: **Vercel（アプリ）+ Supabase（PostgreSQL）**。どちらも無料枠から始められます。

> ⚠️ 重要（添付ファイルについて）
> 添付ファイルは現在サーバーのローカルディスク（storage/uploads）に保存されます。
> Vercel はディスクが永続化されないため、**Vercelに載せる場合は添付機能をS3/Supabase Storageへ差し替えてから**にしてください（改修は小規模・ご相談ください）。
> 先に社内サーバー/VPS（後述の方式B）で運用する場合はそのまま使えます。

## 準備

1. GitHub アカウントを用意し、リポジトリを作成して本プロジェクトをpush
   ```bash
   cd wedding-erp
   git init && git add -A && git commit -m "initial"
   git remote add origin <あなたのリポジトリURL>
   git push -u origin main
   ```
   （.gitignore 済み: node_modules / dev.db / .env / storage）

## 方式A: Vercel + Supabase（SaaS化も見据えた本命構成）

### 1. Supabase（データベース）

1. https://supabase.com でプロジェクト作成（リージョン: Tokyo）
2. Settings → Database → Connection string（URI）をコピー
3. `prisma/schema.prisma` の datasource を変更:
   ```prisma
   datasource db {
     provider = "postgresql"
     url      = env("DATABASE_URL")
   }
   ```
4. ローカルの .env に本番URLを一時設定し、スキーマ反映と初期管理者を作成:
   ```bash
   npx prisma db push
   node scripts/create-admin.cjs "式場 管理者" admin@your-domain.jp "安全なパスワード"
   ```
   （デモデータ用の seed.cjs は本番では実行しないこと）

### 2. Vercel（アプリ）

1. https://vercel.com → Add New → Project → GitHubリポジトリを選択
2. Environment Variables に設定:
   - `DATABASE_URL` = SupabaseのURI
   - `SESSION_SECRET` = `openssl rand -base64 32` で生成した値
3. Deploy。発行されたURL（https://xxx.vercel.app）にアクセスして管理者でログイン
4. 独自ドメインは Vercel の Domains から設定（HTTPS自動）

### 3. 運用設定

- バックアップ: Supabase は日次自動バックアップあり（Pro以上でPITR）
- ユーザー発行: 管理画面（ユーザー・権限）からスタッフ→業者→新郎新婦の順に発行
- 実データ移行: ローカルで `node scripts/import-cases.cjs 実データ.csv`（DATABASE_URLを本番向きにして実行）

## 方式B: 社内サーバー / VPS（添付機能をそのまま使える）

Node.js 18+ が入ったLinuxサーバー（さくらVPS等・月数百円〜）で:

```bash
git clone <リポジトリ> && cd wedding-erp
npm install
# .env に DATABASE_URL（PostgreSQL推奨。SQLiteのままでも小規模なら可）と SESSION_SECRET
npx prisma db push
node scripts/create-admin.cjs "式場 管理者" admin@your-domain.jp "安全なパスワード"
npm run build
npm run start   # ポート3000で起動（pm2 での常駐化を推奨: pm2 start "npm run start" --name wedding-erp）
```

HTTPS化は Caddy または nginx + Let's Encrypt を前面に置く。
バックアップ: `prisma/dev.db`（SQLiteの場合）と `storage/uploads` を日次で別ストレージへコピー。
